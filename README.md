# LLM Java Defect Prediction Pipeline

This project builds a defect prediction workflow for Java code, especially code generated by LLMs.

The pipeline does four main things:

1. Collect Java code from GitHub and LLM generation
2. Generate JUnit test cases for each Java file
3. Analyze compile, runtime, and test defects and export CSV datasets
4. Train ML models and serve a website where users can paste or upload Java code for prediction

## Project Structure

Important files are in [`agents`](F:\MAJOR PROJECT\agents):

- `all_code_generator.py`: collects Java samples from GitHub and Ollama, and labels them as `github` or `llm`
- `test_case_generator.py`: generates JUnit 5 test cases for Java samples
- `defect_analyzer.py`: computes metrics, compile/test defects, defect density, and dataset CSV files
- `train_defect_model.py`: trains and compares multiple ML models using the generated CSV datasets
- `webapp.py`: FastAPI website for user-facing defect prediction

Important data folders:

- `agents/java_samples/`: generated or collected Java source files
- `agents/test_samples/`: generated JUnit test files
- `agents/build/`: compiled classes and JUnit standalone jar
- `agents/model_artifacts/`: trained model and model evaluation outputs

## Features

- Labels code origin as `github` or `llm`
- Generates ML-ready defect datasets
- Computes Java code metrics such as:
  - LOC
  - method count
  - class count
  - import count
  - loop count
  - catch count
  - cyclomatic estimate
  - nesting depth
- Detects:
  - source compile errors
  - runtime errors
  - test compile errors
  - failed tests
- Trains multiple models:
  - Logistic Regression
  - Random Forest
  - Gradient Boosting
- Automatically selects the best model
- Provides a website for paste/upload based defect prediction

## Ollama Setup

The code and test generators use Ollama at:

```text
http://localhost:11434
```

Before running `all_code_generator.py` or `test_case_generator.py`, make sure Ollama is installed and running.

### 1. Check Ollama is installed

```powershell
ollama --version
```

If you see a warning like:

```text
Warning: could not connect to a running Ollama instance
```

that means the Ollama client is installed, but the Ollama server is not running yet.

### 2. Start the Ollama server

Open a terminal and run:

```powershell
ollama serve
```

Keep that terminal open while your generation scripts are running.

You should see a line similar to:

```text
Listening on 127.0.0.1:11434
```

### 3. Check available local models

In another terminal:

```powershell
ollama list
```

### 4. Pull the model used by the scripts

The current scripts use:

```text
codellama:7b
```

If it is missing, run:

```powershell
ollama pull codellama:7b
```

### 5. Then run the generators

```powershell
cd "F:\MAJOR PROJECT\agents"
python all_code_generator.py
python test_case_generator.py
```

## End-to-End Workflow

Run all commands from:

```powershell
cd "F:\MAJOR PROJECT\agents"
```

### 1. Generate Java Samples

```powershell
python all_code_generator.py
```

Outputs:

- `java_samples/`
- `sample_manifest.csv`

### 2. Generate Test Cases

If old tests exist and you want fresh ones:

```powershell
Remove-Item test_samples\*.java
python test_case_generator.py
```

Outputs:

- `test_samples/`

### 3. Analyze Defects and Build Dataset

Make sure the JUnit standalone jar exists in:

- `agents/build/junit-standalone.jar`

Then run:

```powershell
python defect_analyzer.py
```

Outputs:

- `defect_report.csv`
- `defect_dataset.csv`
- `defect_dataset_train.csv`
- `defect_dataset_test.csv`

## Defect Columns

Important output columns:

- `LOC`: logical lines of code
- `CE`: source compile errors
- `RE`: runtime errors
- `TCE`: test compile errors
- `Pass`: tests passed
- `Fail`: tests failed
- `Def`: total defects
- `Density`: defects per KLOC
- `source_origin`: `github`, `llm`, or `user`
- `test_status`: reason tests were executed or skipped

## Defect Density Rule

The density grade uses a research-informed heuristic based on:

- Shah, Morisio, and Torchiano, "An Overview of Software Defect Density: A Scoping Study"
- DOI: `10.1109/APSEC.2012.93`
- Link: https://doi.org/10.1109/APSEC.2012.93

Current thresholds:

- `Clean`: `0`
- `Low`: `< 4.3`
- `Medium`: `4.3 to 7.47`
- `High`: `> 7.47`

## Troubleshooting

### `Pass` and `Fail` are always 0

Possible reasons:

- tests did not compile
- JUnit jar was missing
- generated tests used wrong imports

Check:

- `test_status` column in the CSV
- compiler output in the analyzer

### Analyzer looks stuck

This usually happens when Java programs wait for console input.

The analyzer now skips runtime execution when code contains:

- `Scanner`
- `System.in`

### Ollama connection refused

If you see errors like:

```text
HTTPConnectionPool(host='localhost', port=11434): Max retries exceeded
```

it usually means:

- Ollama is not running
- or the model is not pulled locally

Fix:

```powershell
ollama serve
ollama list
ollama pull codellama:7b
```

### `sklearn` import not resolved in VS Code

Usually VS Code is using a different interpreter than the one where packages were installed.

Check:

```powershell
python -c "import sys; print(sys.executable)"
```

Then select that interpreter in VS Code.
